# Guía de i18n: textos, idiomas y reglas

Todo texto que ve la persona usuaria vive en `data/i18n`. El código nunca contiene textos de producto: los pide por su clave con el API tipado `L`, generado en compilación, y los formatea con `ILocalizer` al pintarlos. Esta guía explica cómo está montado, cómo añadir un texto o un idioma y qué significa cada error.

Decisiones de fondo: blueprint §8.5, D18 y ADR-0011. Requisitos: IDI-001 a IDI-006 del catálogo.

## 1. Piezas

| Pieza | Dónde | Qué hace |
|---|---|---|
| Textos | `data/i18n/strings.<idioma>.json` | Un objeto JSON plano: clave → texto. Hoy `es` (por defecto) y `en`. |
| Idiomas | `data/i18n/locales.json` | Idioma por defecto, nombre propio, separador decimal y reglas de plural CLDR de cada idioma. |
| Marcadores | `data/i18n/placeholders.json` | Vocabulario cerrado de marcadores con su tipo y su descripción para quien traduce. |
| Claves sin uso permitidas | `data/i18n/allow-unused.txt` | Claves que pueden no usarse en el código (huérfanas pendientes de decisión y propuesta P2). |
| Receta de importación | `data/i18n/handoff-import.json` | La conversión revisada a mano desde el paquete de diseño. |
| Generador | `generators/Clicalo.Generators/Localization` | Valida los datos (errores `CLCI0xx`) y genera `MessageKey`, `L` y `MessageCatalog` en `Clicalo.Domain.Messages`. |
| Tipos de mensaje | `src/Clicalo.Domain/Messages` | `Message` (clave + argumentos con nombre), `MessageText`, `MessageValue`… |
| Formateador | `src/Clicalo.Application/Localization` | `ILocalizer`, `Localizer`, reglas de plural CLDR, `LocalizationContext` (cambio de idioma en caliente). |
| Herramienta | `tools/Clicalo.DevCli` | `i18n-check` e `i18n-import`. |

La carga de los JSON en ejecución es trabajo de Infrastructure: lee los archivos y llama a `LanguagePack.Create` y a `new LocaleInfo(...)`.

## 2. Formato de los textos

```json
{
  "search": "Buscar acción en todos los perfiles…",
  "createFor": "Crear para {app}",
  "comboN_one": "{count} tecla · se guarda solo",
  "comboN_other": "{count} teclas · se guarda solo"
}
```

- **Claves.** `[A-Za-z][A-Za-z0-9]*`. Son las claves originales del paquete, que el catálogo cita como `[clave]`: no se renombran. El miembro generado es la clave con la primera letra en mayúscula (`createFor` → `L.CreateFor`).
- **Marcadores con nombre.** `{nombre}` con `nombre = [a-z][A-Za-z0-9]*`, siempre uno de `placeholders.json`. Para escribir una llave literal se dobla: `{{` y `}}`. Cualquier otra llave es un error.
- **Plurales.** Una familia de plural es un grupo de claves con sufijo de categoría CLDR (`_zero`, `_one`, `_two`, `_few`, `_many`, `_other`), como en i18next v4, que es el formato que entiende Weblate. La familia elige su forma con el marcador `{count}`. `_other` es obligatoria y cada idioma exige además las categorías de sus reglas (`es` y `en`: `one` y `other`). Una forma puede omitir `{count}` (por ejemplo «Añadir uno»), pero la familia debe usarlo en alguna.
- **Frases con varias cantidades.** Una familia solo elige por `{count}`. Si una frase tiene dos cantidades, cada cantidad es un mensaje anidado con su propio plural. Ejemplo: `migT` = «Importado desde tu versión anterior: {profiles} y {shortcuts}», con `migTProfiles_one/_other` y `migTShortcuts_one/_other`. Quien traduce sigue controlando el orden de la frase y no se concatenan fragmentos (IDI-004).
- **Tipografía.** Comillas «» en español y “” en inglés; nunca comillas rectas. «Clícalo» con tilde (TEM-008). Hay pruebas que lo comprueban.
- **Espacios.** Se conservan tal cual (por ejemplo `copySuffix` = « (copia)»).

### Marcadores disponibles

| Marcador | Tipo | Uso |
|---|---|---|
| `{app}` | texto | Nombre visible de una aplicación. |
| `{profile}` | texto | Nombre de un perfil; puede ser un mensaje traducido. |
| `{profiles}`, `{shortcuts}` | texto | Frases ya traducidas con una cantidad (`migTProfiles`, `migTShortcuts`). |
| `{name}` | texto | Nombre de un atajo o elemento. |
| `{keys}` | texto | Combinación con los nombres de tecla ya traducidos. |
| `{version}` | texto | Número de versión. |
| `{count}` | entero | Cantidad; elige la forma de plural. |
| `{index}`, `{total}` | entero | Posición (desde 1) y total. |

Tipos: `text` acepta texto literal (datos de la persona usuaria, que se muestran tal cual) o un `Message` anidado, que se traduce en el mismo idioma que el mensaje que lo contiene; `integer` es `long`; `number` es `decimal`. Los parámetros generados siguen el **orden de declaración** de `placeholders.json`, no el del texto: así, reescribir una frase nunca cambia el orden de los argumentos en las llamadas.

## 3. Cómo añadir un texto

1. Elige una clave corta en inglés técnico o sigue el estilo de las vecinas (`camelCase`).
2. Añádela en **todos** los `strings.*.json` y en la misma posición relativa. Usa solo marcadores del vocabulario. Mientras `cl check` ejecute `i18n-import --check`, `strings.*.json` debe salir de la receta: declara la clave en `added` de `handoff-import.json` con `after` (la clave tras la que va), `notes` y **o bien** `text` (un texto por idioma) **o bien** `plural` (las formas por idioma, con `other`), y vuelve a importar con `dotnet run --project tools/Clicalo.DevCli -- i18n-import`.
3. Si el texto es nuevo para el producto (no viene del paquete), regístralo en §7 del catálogo para que el usuario lo ratifique (blueprint §8.5).
4. Compila. El generador crea el miembro:

   ```csharp
   // Sin marcadores: una propiedad con el mensaje ya construido.
   Message title = L.Search;
   // Con marcadores: un método con un parámetro por marcador.
   Message line = L.SugLine(app: "Word", count: 3);
   Message nested = L.MigT(L.MigTProfiles(2), L.MigTShortcuts(210));
   ```

5. Guarda el `Message` en el estado (un aviso, un error) y formatéalo **al pintar** con `ILocalizer.Format`. Así el cambio de idioma lo vuelve a traducir (IDI-001).
6. Ejecuta `cl i18n-check` (`dotnet run --project tools/Clicalo.DevCli -- i18n-check`).

**Añadir un marcador:** decláralo en `placeholders.json` con `type` y `description` (en español, para quien traduce). El orden de declaración es el orden de los parámetros.

**Añadir un plural:** sustituye la clave por `clave_one` y `clave_other` en todos los idiomas y usa `{count}`. El nombre del miembro no cambia (`L.Clave(count)`).

## 4. Cómo añadir un idioma (IDI-006)

No hace falta tocar código:

1. Crea `data/i18n/strings.<código>.json` con todas las claves (Weblate lo exporta en formato «i18next JSON v4»; configura su comprobación de marcadores con la expresión `\{[a-z][A-Za-z0-9]*\}`).
2. Añade una entrada en `locales.json`:

   ```json
   {
     "code": "pt-BR",
     "culture": "pt-BR",
     "nativeName": "Português (Brasil)",
     "shortName": "PT",
     "decimalSeparator": ",",
     "plural": { "one": "i = 0..1 @integer 0, 1" }
   }
   ```

   Las reglas se copian tal cual del archivo `plurals.xml` de CLDR (sintaxis de UTS #35, parte 3). `other` es implícita. Las muestras `@integer` y `@decimal` son opcionales, pero conviene conservarlas: una prueba comprueba que las reglas clasifican bien sus propias muestras.
3. Compila: el generador exige paridad de claves, marcadores y formas de plural con el idioma por defecto. Un texto que falte en un idioma nuevo que se cargue en ejecución se muestra en el idioma por defecto, nunca rompe la interfaz.

## 5. Reglas

- Ningún texto de producto en el código ni en XAML: siempre `L.*` o `{loc:T clave}` (IDI-002, CLC0006).
- Nada de construir mensajes concatenando fragmentos: una frase es una clave, con marcadores o con mensajes anidados (IDI-004).
- Los números se escriben sin separador de miles; los decimales, con el separador de `locales.json` (coma en español, punto en inglés). La escala de un `decimal` se respeta (`0.50m` → «0,50»).
- Las reglas de plural de `es` y `en` usan solo `one` y `other`. La categoría `many` que CLDR define para el español solo afecta a notación compacta de millones («1 millón de…»), que Clícalo no usa.
- Condición vinculante con el paquete: con los argumentos de muestra, cada texto importado se ve **idéntico** al original (`VisibleTextSnapshotTests`). Si el usuario ratifica una corrección de texto (catálogo §9), esa prueba se actualiza en el mismo PR.
- Claves huérfanas: `i18n-check` falla si una clave de `allow-unused.txt` no existe, está repetida o ya se usa. Con `--strict-unused` también falla si una clave no se usa y no está en la lista; se activará en la CI cuando la interfaz exista (M3).

## 6. Herramienta: `cl i18n-check` e `cl i18n-import`

```text
dotnet run --project tools/Clicalo.DevCli -- i18n-check [--strict-unused] [--repo <dir>]
dotnet run --project tools/Clicalo.DevCli -- i18n-import [--check] [--repo <dir>]
```

- **`i18n-check`** ejecuta exactamente la validación del generador (el mismo código), comprueba la sintaxis de las reglas CLDR con el analizador de ejecución y contrasta `allow-unused.txt` con el uso real: `L.Miembro` en `src/**/*.cs`, `{loc:T clave}` en `src/**/*.xaml` y propiedades `…Key` de `data/**/*.json`.
- **`i18n-import`** reconstruye `strings.*.json` desde `docs/design/handoff/data` con la receta `handoff-import.json`: cambia cada marcador de una letra por su nombre (`{a}`→`{app}`, `{p}`→`{profile}`, `{n}`→`{count}`, `{k}`→`{keys}`, `{i}`→`{index}`, `{t}`→`{total}`, `{v}`→`{version}`, `{x}`→`{name}`, con excepciones por clave), añade las formas de plural revisadas y las claves nuevas. Un marcador que la receta no conozca es un error. Con `--check` no escribe nada y falla si `data/i18n` no coincide con una importación limpia. Tras los cambios de texto ratificados (catálogo §9), la receta deja de reproducir los archivos y `--check` deja de usarse en la CI.
- Salida en formato de MSBuild (`ruta(línea,columna): error ID: mensaje`), que VS Code enlaza, y una última línea legible por Narrador. Códigos de salida: 0 sin problemas, 1 problemas, 2 uso incorrecto (verbo u opción desconocidos, con la ayuda).

## 7. Errores

Todos son errores de compilación (o de `i18n-check`) y señalan la línea y la columna exactas del JSON.

| Id | Qué pasa | Cómo se corrige |
|---|---|---|
| <a id="clci001"></a>CLCI001 | JSON inválido (incluidas claves repetidas). | Corrige la sintaxis en la posición indicada. |
| <a id="clci002"></a>CLCI002 | Una clave existe en un idioma y falta en otro. | Añádela en el idioma que falta (o bórrala en todos). |
| <a id="clci003"></a>CLCI003 | La misma clave usa marcadores distintos en dos idiomas. | Usa el mismo conjunto de marcadores en todos los idiomas. |
| <a id="clci004"></a>CLCI004 | Marcador que no está en `placeholders.json`. | Usa uno del vocabulario o declara uno nuevo. |
| <a id="clci005"></a>CLCI005 | Texto vacío o solo espacios. | Escribe el texto. |
| <a id="clci006"></a>CLCI006 | Clave con caracteres no válidos o sufijo de plural desconocido. | Solo letras y dígitos; sufijos `_zero`…`_other` en minúsculas. |
| <a id="clci007"></a>CLCI007 | Dos claves generan el mismo miembro (`abc` y `Abc`) o uno reservado (`toString`, `equals`…). | Renombra una de las claves. |
| <a id="clci008"></a>CLCI008 | Llave suelta o marcador mal escrito (`{Count}`, `{a b}`). | Corrige el marcador o dobla la llave (`{{`, `}}`). |
| <a id="clci009"></a>CLCI009 | A una familia de plural le falta `_other` o una categoría que exige el idioma. | Añade la forma. |
| <a id="clci010"></a>CLCI010 | Forma de plural que las reglas del idioma no usan (`_few` en español). | Bórrala. |
| <a id="clci011"></a>CLCI011 | Familia de plural sin `{count}` numérico. | Usa `{count}` en alguna forma; debe ser `integer` o `number`. |
| <a id="clci012"></a>CLCI012 | Clave plural en un idioma y simple en otro, o las dos cosas en el mismo idioma. | Usa la misma forma en todos los idiomas. |
| <a id="clci013"></a>CLCI013 | `locales.json` falta o es inválido, hay un idioma sin archivo o un archivo sin idioma, o una regla CLDR no se entiende. | Corrige `locales.json` o el nombre del archivo (`strings.<código>.json`). |
| <a id="clci014"></a>CLCI014 | `placeholders.json` falta o es inválido. | Cada marcador necesita `type` (`text`, `integer`, `number`) y `description`. |
| <a id="clci015"></a>CLCI015 | Un archivo de textos no es un objeto plano de cadenas. | Sin objetos anidados ni números: solo `"clave": "texto"`. |
| CLCI100 | `i18n-import`: el paquete o la receta tienen un problema, o `data/i18n` no coincide con la importación. | Revisa la receta o vuelve a importar. |
| CLCI101 | `allow-unused.txt` falta o lista algo que no es una clave. | Usa la clave base, sin sufijo de plural. |
| CLCI102 | Una clave de `allow-unused.txt` ya se usa. | Quítala de la lista. |
| CLCI103 | Una clave aparece dos veces en `allow-unused.txt`. | Deja una. |
| CLCI104 | Con `--strict-unused`: clave sin uso que no está en la lista. | Úsala, bórrala o añádela a la lista con su motivo. |

## 8. En ejecución

- `ILocalizer` es una instantánea inmutable de un idioma: se puede usar desde cualquier hilo.
- `LocalizationContext` guarda un `Localizer` por idioma y cambia el actual de forma atómica; `LanguageChanged` avisa en el hilo que hizo el cambio. En UI.Wpf, un `LocalizationSource` por dispatcher lo escucha y repinta (blueprint §8.5).
- Si falta un argumento se muestra `{nombre}`; si falta una clave en un idioma se usa el idioma por defecto; si la clave no existe se muestra la clave. Nada de eso lanza excepciones: la compilación ya garantiza la paridad de `es` y `en`, y un idioma cargado en ejecución nunca debe romper la interfaz. Las entradas inválidas de un archivo cargado quedan en `LanguagePack.Problems` para el registro.
